# Explore Tasks — каталог, фильтры и сохранённые задачи

## Показ за минуту

1. Выполните `npm start`, откройте **http://localhost:3000/demo.html#catalog**.
   Демо добавляет 20 разнообразных задач к предыдущим примерам; данные отделены от сервера.
2. Выберите студенческую роль. Для Match откройте «Мой профиль», заполните пример Ali
   и сохраните его. Вернитесь в каталог: по умолчанию используется рейтинг готовности; включите рекомендации для сортировки по соответствию.
3. Введите `React dashboard`, выберите несколько категорий или навыков.
4. Удалите отдельную активную метку либо нажмите Сбросить. Проверьте Показать ещё.
5. Сохраните карточку значком закладки, включите Только сохранённые и обновите страницу.
6. На узком экране нажмите Фильтры: откроется панель с теми же настройками.
7. Откройте карточку с прошедшим дедлайном: приём закрыт; сервер также отклонит такой отклик.

Основной каталог: **http://localhost:3000/#catalog**. Он использует только данные сервера.
Все ранее опубликованные задачи доступны, но старые записи без метаданных не получают
выдуманные сроки, навыки или бейджи. Дополнить новые поля можно в редакторе задачи.

Общий каталог сортируется по готовности; рекомендации по соответствию включаются отдельно. Рейтинг готовности виден на каждой карточке. Дополнительные фильтры свёрнуты.

## URL и правила поиска

Сохранён существующий hash routing; новый пример ссылки:

`#catalog?category=backend,fullstack&skills=Python,FastAPI&difficulty=medium&sort=match&page=1`

Карточки открываются через прежний `#task/:id`. Ссылка «Все задачи» возвращает
последнюю конфигурацию каталога. Back/Forward и обновление восстанавливают фильтры.
Демо-роль запоминается в localStorage, закладки — отдельно для каждой команды.

- Ввод поиска объединяется за **400 мс**. Все слова должны встретиться в названии,
  описании, компании, категории или навыках; слово может находиться в любом из этих полей.
- Разные группы фильтров соединяются через AND. Значения одной группы — через OR,
  кроме Skills: задача должна содержать все выбранные навыки. Поддерживаются алиасы
  из Match (React.js, Postgres и т. п.). В списке навыков есть отдельный локальный поиск.
- Минимальный Match — 60, 75 или 90. Recommended означает **75%+**;
  если выбран более высокий порог, используется он.
- Match показывается только при наличии хотя бы одного навыка и уровня студента.
  Без достаточного профиля отображается приглашение его заполнить; число не подставляется.
- Best Match используется по умолчанию для такого профиля, иначе Newest.
  Также доступны Popular, Deadline Soon, Easy → Hard, Shortest и прежний Readiness rating.
- Все фильтры и сортировка выполняются до пагинации. Изменение фильтра сбрасывает page на 1;
  сортировка сохраняет фильтры. Показать ещё добавляет следующую порцию из 12 задач.
- Ссылка с `page=2` при прямом открытии показывает вторую страницу; доступен переход
  к первой. Во время текущего сеанса Показать ещё накапливает карточки без дублей.
- Старый запрос отменяется при смене условий; его поздний ответ не заменяет новый результат.
  Ошибка загрузки/закладки отображается с возможностью повторить действие.

## Метаданные и границы

В редактор добавлены `durationWeeks`, `teamSize`, `workFormat`, `applicationDeadline`.
Имена старых полей сохранены: `deadline` по-прежнему означает длительность проекта
в свободном тексте, а не дату окончания приёма заявок.

- Для Duration используется числовое `durationWeeks`, если оно указано.
  Иначе распознаются простые сроки вроде «3 недели», «2–3 weeks», «10 дней», «2 месяца».
  Для диапазона берётся верхняя граница; месяц в фильтре равен четырём неделям.
- Интервалы длительности: `<1`, `1–2`, `>2–4`, `>4–8`, `>8` недель.
  Неопределённый срок не проходит выбранный фильтр длительности и сортируется последним.
- Команды: Individual, 2–3, 4–5, 5+. Пересечение диапазонов допускается:
  группа из пяти человек подходит фильтрам 4–5 и 5+.
- Форматы: Remote, Hybrid, On-site. Неуказанный формат не угадывается по описанию.
- Дедлайн — `YYYY-MM-DD`, включительно до **23:59:59.999 UTC**.
  После этого `canApply=false` и сервер возвращает 409 при отправке отклика.
- Open означает незавершённый приём и действующий дедлайн либо отсутствие даты закрытия.
  Closing soon — открытая задача с дедлайном в ближайшие семь суток.
- NEW — открытая задача, опубликованная за последние семь суток.
  `createdAt` / `publishedAt` выставляет сервер, повторная публикация не обновляет дату.
- POPULAR — не меньше пяти разных команд с откликами. FEATURED — только явный флаг
  в исходных данных; не выводится из случайного числа. На карточке максимум два бейджа.
- `applicantsCount` считает уникальные команды, `offerCount` — все варианты предложений.
  Повторные предложения по-прежнему разрешены, пока приём открыт.

Фильтр готовности 0–39 / 40–69 / 70–89 / 90–100 сохранён отдельно от Match.

## API

Для совместимости **GET `/api/tasks` без параметров** и **GET `/api/tasks?all=true`**
возвращают прежний массив. Новый UI использует `GET /api/tasks?view=catalog` с фильтрами.
Запросы с параметрами каталога также возвращают объект с пагинацией.

Параметры: `search`, `category`, `skills`, `difficulty`, `duration`, `teamSize`,
`workFormat`, `status`, `minMatch`, `recommended`, `saved`, `readiness`, `sort`, `page`, `limit`.
Массивы передаются через запятую. `studentId` — идентификатор демонстрационной команды
для расчёта Match и её закладок. По умолчанию limit=12, максимум 48.

```json
{
  "items": [{
    "id": "task-id", "title": "CRM Dashboard", "company": "Компания",
    "requiredSkills": ["React", "PostgreSQL"], "difficulty": "Medium",
    "durationWeeks": 3, "teamSize": "2-3", "workFormat": "Remote",
    "applicationDeadline": "2026-10-05", "applicantsCount": 4,
    "matchScore": 87, "matchLabel": "Strong Match", "matchResult": {},
    "isSaved": false, "canApply": true, "isNew": true, "isClosingSoon": false
  }],
  "pagination": { "page": 1, "limit": 12, "total": 24, "hasMore": true },
  "facets": { "skills": ["React", "PostgreSQL"] },
  "matchAvailable": true,
  "sort": "match"
}
```

В примере поля сокращены; score иллюстративный. Настоящие Match вычисляются существующим
алгоритмом. `matchResult` содержит полную проверяемую расшифровку. Компания сохраняет
прежний строковый формат. Для каталога нет вызовов LLM и запросов Match на каждую карточку.

`PUT /api/students/:studentId/saved/:taskId` с `{saved:true|false}` записывает закладку.
Ответ: `{taskId,isSaved}`. Закладки хранятся в `savedTasks` JSON-базы и переживают перезапуск.
`GET /api/tasks/:id?studentId=...` возвращает дополнительные сведения карточки и Match.

Авторизация остаётся прежней демонстрационной: `studentId` не является подтверждением
личности. Серверное разграничение аккаунтов относится к отдельному этапу backend.

## Компоненты и проверки

`catalog-engine.cjs` содержит единые правила для Node и автономного демо.
`catalog-components.js` содержит TaskCatalogPage, TaskCard, TaskФильтры, FilterChip,
SearchBar, SortSelect, TaskSkeleton, EmptyState и SavedButton.
`catalog-page.js` управляет отдельным состоянием фильтров, URL, запросами и закладками.
`catalog-demo.cjs` создаёт 20 примеров с разными условиями и настоящими демо-откликами.

Тесты проверяют сочетания фильтров и поиска, границы, сортировки, отсутствие дублей,
восстановление query, совместимость API, сохранение закладок, запрет просроченных откликов,
недостаточный профиль, экранирование карточки, debounce, отмену устаревшего запроса
и Показать ещё. UI-контроллер проверяется через модель DOM; это не визуальный браузерный тест.

В среде агента браузер недоступен. Перед выступлением проверьте карточки, фокус,
мобильную панель и сценарий сохранения на обычной и узкой ширине окна.

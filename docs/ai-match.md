# Соответствие задачи команде

Профиль поддерживает состав команды: навыки объединяются без дублей, уровень и время на участника берутся по минимальному указанному значению. Пробел у участника оставляет показатель неизвестным. Бизнес видит снимок состава на момент отклика. Проект учитывается как подтверждённый опыт только после приёмки всех этапов.

## Быстрый показ

Запустите `npm start` и откройте **http://localhost:3000/demo.html#match-demo**.
Страница загрузит явно демонстрационный профиль Ali и задачу CRM Dashboard.
Ключ OpenAI для этого сценария не нужен. Нажмите **Как рассчитано соответствие**:

| Критерий | Оценка | Вес | Вклад |
|---|---:|---:|---:|
| Skills | 80 | 50% | 40 |
| Experience | 92 | 20% | 18.4 |
| Interest | 100 | 10% | 10 |
| Difficulty | 90 | 10% | 9 |
| Availability | 100 | 10% | 10 |

Итого `round(40 + 18.4 + 10 + 9 + 10) = 87%`, **Высокое соответствие**.
Четыре из пяти навыков совпадают; Docker отсутствует. Два завершённых проекта
похожи по технологиям, Intermediate подходит Medium, 15 часов покрывают требуемые 10.
Это вычисление по демонстрационным данным, не специально подставленный процент.

Нажмите **Apply**, заполните предложение и отправьте его. Переключитесь на «Бизнес»
и откройте предложения к CRM Dashboard: там будет Ali, его навыки и 87% Match.
Выбор и отклонение остаются ручными. Демо-сценарий заменяет профиль представителя
текущей демонстрационной команды в отдельном локальном хранилище `/demo.html`.
Он не меняет профили и задачи основного сервера.

## Основной интерфейс

1. В основной версии войдите в аккаунт команды; в демо выберите студенческую роль. Откройте **Мой профиль**.
2. Укажите имя, навыки, уровень, желаемую сложность, интересы, часы в неделю,
   опыт, ссылки, технологии репозиториев и проекты. Нажмите «Сохранить профиль».
3. В каталоге и на странице задачи отображается Match с числом и текстовой оценкой.
4. В подробностях доступны пять критериев, их вес и вклад, сильные стороны,
   отсутствующие навыки и рекомендации без обещаний будущего процента.
5. На основном сервере кнопка «Объяснить с OpenAI» создаёт дополнительное пояснение.
   Используются те же `OPENAI_API_KEY` / `OPENAI_MODEL`, что у AI-интервью.
   При ошибке или отсутствии ключа остаётся объяснение по критериям.

В редактор задачи добавлено поле **Нагрузка · Часов в неделю на участника**.
Срок в неделях и недельная нагрузка — разные поля. Неизвестную нагрузку оставляйте пустой.
Соответствие — отдельная от готовности оценка. Общий каталог всегда открывается по готовности; рекомендации по соответствию включаются отдельно.

## Формула match-v1

`round(skills × 0.5 + experience × 0.2 + interest × 0.1 + difficulty × 0.1 + availability × 0.1)`.

- **Skills:** доля уникальных требуемых навыков, указанных в skills профиля, × 100.
  Сравнение без учёта регистра, с нормализацией пробелов и алиасов
  React.js / React, TS / TypeScript, Postgres / PostgreSQL, RESTful API / REST API и др.
  Повторяющиеся навыки не увеличивают балл. Java не совпадает с JavaScript.
- **Experience:** `min(похожих завершённых проектов / 2, 1) × 60 + доля требуемых
  технологий в указанном опыте × 40`. Похожий проект завершён и совпадает хотя бы
  по одному навыку или направлению. Проекты без названия, дубли названий или ссылок
  не увеличивают число проектов. Технологии ищутся в описаниях опыта, явно указанных
  технологиях GitHub и навыках завершённых проектов. Это анализ предоставленных
  сведений, не верификация уровня владения технологией.
- **Interest:** 100 при совпадении хотя бы одного направления, иначе 0.
  Fullstack и «Веб-разработка» совместимы с Frontend / Backend;
  «ИИ и автоматизация» — с AI, «Аналитика» — с Data, «Дизайн» — с Design.
- **Difficulty:** таблица ниже. Если указана иная желаемая сложность, результат
  умножается на 0.7. Неуказанное предпочтение не уменьшает балл.
- **Availability:** `min(доступные часы / требуемые часы, 1) × 100`.
  Часы от 0 до 168; отсутствующая или нулевая нагрузка задачи считается неизвестной.

| Уровень | Easy | Medium | Hard |
|---|---:|---:|---:|
| Beginner | 100 | 40 | 10 |
| Intermediate | 100 | 90 | 50 |
| Advanced | 100 | 100 | 100 |

Неизвестные сведения не дают баллов. Веса не перераспределяются,
а карточка показывает «Предварительно» и список недостающих данных.
Пустой список навыков задачи не считается стопроцентным совпадением.
Все вычисления выполняются до округления итогового процента; breakdown отображается
с точностью до двух знаков, contributions — с точностью до сотых балла.

Диапазоны: 90–100 Excellent, 75–89 Strong, 60–74 Good, 40–59 Partial, 0–39 Low Match.
Это правила MVP, а не обученная или эмпирически откалиброванная оценка успеха проекта.

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/match` | Детерминированная оценка `{student, task}` |
| POST | `/api/match/explain` | Тот же расчёт + опциональное пояснение OpenAI |
| GET | `/api/students/:id/profile` | Собственный профиль команды |
| PUT | `/api/students/:id/profile` | Сохранение редактируемых полей профиля |

```json
{
  "student": {
    "name": "Ali",
    "skills": ["React", "TypeScript", "PostgreSQL", "REST API"],
    "experience": ["Разрабатывал REST API"],
    "interests": ["Frontend", "Backend"],
    "level": "Intermediate",
    "preferredDifficulty": "Medium",
    "availabilityHours": 15,
    "githubUrl": "",
    "portfolioUrl": "",
    "githubTechnologies": ["React", "TypeScript", "PostgreSQL", "REST API"],
    "projects": [
      {"title": "CRM", "category": "Fullstack", "skills": ["React"], "completed": true, "url": ""},
      {"title": "Запись", "category": "Frontend", "skills": ["React"], "completed": true, "url": ""}
    ]
  },
  "task": {
    "title": "CRM Dashboard",
    "requiredSkills": ["React", "TypeScript", "PostgreSQL", "REST API", "Docker"],
    "category": "Fullstack",
    "difficulty": "Medium",
    "requiredHours": 10
  }
}
```

Ответ содержит `matchScore`, `label`, `breakdown`, `weights`, `contributions`,
`matchedSkills`, `missingSkills`, `strengths`, `recommendations`, `missingData`,
`evidence`, `explanation`, `explanationSource`, `task` и `version: "match-v1"`.
AI-схема содержит только текст explanation. Числа, лейблы и списки рассчитывает
алгоритм; даже лишний score в ответе модели не используется.
В OpenAI передаются только рассчитанные причины и рекомендации, без ссылок и имени.

Некорректный ввод возвращает 400. Недоступность AI в `/match/explain` возвращает
200 с исходным алгоритмическим пояснением и `explanationNotice`.
Обычный `/match` не вызывает OpenAI. Требования задачи принимаются строкой через
запятые/переносы либо массивом; профиль нормализуется в массивы.

## Данные и совместимость

- Единый `public/match-engine.cjs` работает и на Node, и обычным script в автономном
  демо. Формулы не дублируются. `match-ui.js` содержит профиль, блок оценки и dialog.
- `students` добавляется в существующий JSON без удаления задач, предложений и этапов.
- Профиль поддерживает до 20 участников: навыки объединяются без дублей, уровень и часы учитывают самого ограниченного участника. Старые профили одного участника также поддерживаются.
- При отправке предложения сервер сам берёт сохранённый профиль и рассчитывает
  `matchSnapshot`. Переданный клиентом score игнорируется. Снимок не меняется при
  последующем редактировании профиля. Старые предложения без снимка имеют пояснение.
- Подтверждённые бизнесом этапы возвращаются как `completedTasks` и учитываются
  в опыте; они не записываются из редактируемого профиля. `/api/match` с произвольным
  телом считает переданные сведения, а не проверяет их происхождение.
- Низкий Match, отсутствующий профиль или старые неполные метаданные не запрещают
  отправить предложение и не выбирают команду автоматически.
- GitHub/portfolio не скачиваются. Технологии и личные проекты введены участником;
  ссылка без таких сведений не даёт дополнительных баллов.
- Идентификатор команды и переключатель ролей остаются демонстрационными.
  Полноценная авторизация и разграничение профилей — отдельная задача backend.

## Проверка

`npm test` проверяет точную формулу и демо 87%, алиасы и границы, неполные данные,
дубли проектов, ошибки ввода, сохранение профиля и снимка отклика, подтверждённый
прогресс, отсутствие автоматического выбора, паритет offline/server и устойчивость
UI к запоздавшему ответу. Запрос пояснения OpenAI проверен на подменённом ответе.
`npm run lint` проверяет синтаксис всех модулей.

Реальный вызов OpenAI требует ключа. В среде агента нет доступного браузера,
поэтому перед выступлением нужно проверить внешний вид на обычной и мобильной ширине.

# Изменения после оценки MVP

## Запуск и демонстрация

`npm start` → http://localhost:3000. Node.js 22.9+, установка пакетов не нужна.

- `/` — каталог для всех, создание аккаунта и вход для действий. Роль фиксируется при регистрации.
- `/demo.html` — отдельное локальное демо с переключением бизнеса и команды. Оно не вызывает защищённые API и не меняет серверные данные.
- `/case.html` — сценарий защиты и новая копия учебного кейса на каждую репетицию.
- `/prototype.html?variant=grid` и `?variant=list` — два представления работающего учебного прототипа записи. Данные локальные; это не сервис реальных бронирований.

Кейс студии, команды и метрики явно учебные. Нет заявления о реальном внедрении или измеренной экономии времени.

## Единая готовность

`public/readiness-engine.cjs` задаёт общую шкалу для сервера, фронтенда и автономного демо: контекст 20, данные 20, результат 15, приёмка 15, ограничения 10, пользователи 10, контакт 10. Пустые поля и явные ответы «Пока не знаю» не дают баллов. Потребность и формат взаимодействия отображаются отдельными недостающими сведениями.

Оценка отражает полноту, а не правдивость или качество текста. Подробности видны в карточке и редакторе. Редактор считает её локально тем же модулем; публикация и каталог пересчитывают по тем же правилам на сервере.

`POST /api/quality` — отдельная проверка качества OpenAI по кнопке, возвращает `{source, suggestions: [{key,label,hint}]}` без рейтинга. Старый семантический анализ сохранён для этих рекомендаций. Набор текста не вызывает OpenAI. Ключ не настроен — функция сообщает об этом, остальные возможности работают.

## Интервью и интерфейс

- Серверный `interview-rules.cjs` не позволяет готовой карточке обойти три уточнения. При полном описании задаются контекстные подтверждения результата, границ и доступных материалов. Общий предел — пять ответов.
- Тот же минимум действует в автономном демо. Без ключа включается явно подписанное шаблонное уточнение; ошибка настроенного провайдера не выдаётся за успешный AI-ответ.
- Общий каталог по умолчанию сортируется по готовности. Рекомендации включаются отдельно и сортируются по соответствию профилю.
- Рейтинг виден на каждой плитке; бизнес не получает приглашение заполнить студенческий профиль.
- Основные действия на русском. Дополнительные фильтры, метаданные и AI-действия свёрнуты. Срок и размер команды вводятся по одному разу; поля фильтра выводятся из этих значений.

## Аккаунты и права

`src/auth.js`: пароль хранится как salted scrypt hash, сессия — случайный токен в HttpOnly / SameSite=Strict cookie на 12 часов. Встроенные сессии живут в одном процессе: после перезапуска нужно снова войти. Есть ограничение попыток входа с одного адреса. Сервер не принимает роль и идентификатор команды из тела отклика как разрешение.

| Маршрут | Доступ |
|---|---|
| `POST /api/auth/register` | `{login,password,name,role}`; роли `business` / `student` |
| `POST /api/auth/login` | `{login,password}` |
| `POST /api/auth/logout` | `{}` |
| `GET /api/auth/session` | `{user: null}` или публичные id, login, name, role |
| `GET /api/tasks?all=true` | Бизнес: только свои задачи и черновики. Команда: опубликованные задачи |
| `POST/PATCH tasks`, publish, selection, решения по откликам | Только бизнес-владелец |
| `GET proposals` | Владелец видит все отклики; команда только свои; гость не видит контакты предложений |
| Профиль и закладки | Только собственный профиль команды |
| `GET /api/stages` | Только свои этапы или этапы собственных бизнес-задач |
| `POST /api/stages/:id/submit` | Только назначенная команда |
| `POST /api/stages/:id/review` | Только владелец задачи |

`createApp(..., {authorize:false})` используется исключительно явно из старых тестов домена. Сервер при `npm start` всегда включает проверки. Старые записи без владельца сохраняются; они не присваиваются первому зарегистрированному пользователю. Для управляемого показа используйте отдельное демо или создайте задачу из аккаунта.

## Команда и этапы

Профиль поддерживает `members: [{name,role,skills,level,availabilityHours}]`. Навыки объединяются с удалением дублей и алиасов. Уровень и часы на человека берутся по самому ограниченному участнику; пропуск у одного участника сохраняет показатель неизвестным. Это объяснено в форме. Общие проекты и интересы остаются в профиле. Бизнес видит снимок состава и соответствия на момент отклика.

`stagePlan` — JSON-строка с 2–3 объектами `{title,criteria,points}`, сумма баллов ровно 100. Редактор предлагает три этапа на 20/30/50 баллов. Они доступны в карточке до отклика и копируются каждой выбранной команде после ручного подтверждения бизнеса.

Команда подтверждает план через `POST /api/tasks/:id/plan/accept` с `{}`. После этого отправляет результат первого этапа. Следующий доступен только после приёмки предыдущего. Бизнес принимает результат или возвращает с обязательным комментарием. Повторная приёмка возвращает 409. После выбора команд условия задачи зафиксированы. В подтверждённый опыт команды проект попадает только после приёмки всех его этапов.

Существующие этапы старой версии сохранены, включая их прежние баллы и результаты.

## Проверки и границы

`npm test` проверяет старые сценарии и новые права, подмену команды, запрет самостоятельной приёмки, общий рейтинг, минимум вопросов, навыки нескольких участников, согласование/порядок этапов, сохранение и повторное начисление.

`npm run lint` проверяет весь JavaScript, включая скрипт прототипа внутри HTML. Запросы OpenAI в тестах подменяются; действующий ключ нужен для отдельного реального прогона. В среде агента нет доступного браузера для визуальной проверки — адаптивность и полный клик-сценарий нужно проверить перед защитой.

Хранилище рассчитано на один процесс. Нет восстановления пароля, приглашений в команду и OAuth. Это ограничения текущего MVP.

Правило полноты: поле получает свой фиксированный вес, если содержит минимум 3 буквы или цифры и не является очевидной заглушкой, повтором одного символа, короткого буквенного блока (от трёх повторений) или одного слова. Иначе — 0 баллов с пояснением в подсказке. Краткие обозначения CSV/CRM и содержательное «Нет ограничений» допускаются. Это базовая проверка полноты, а не автоматическая оценка достоверности текста.

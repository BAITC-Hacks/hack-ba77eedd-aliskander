# AI Task Generator + AI Interview

## Запуск для команды

1. Установите Node.js 22.9 или новее. Зависимости скачивать не нужно.
2. Скопируйте `.env.example` в `.env` в корне репозитория.
3. Укажите свой `OPENAI_API_KEY` в `.env`. Не добавляйте ключ в код или сообщения.
4. При необходимости задайте `OPENAI_MODEL` (по умолчанию `gpt-4o-mini`).
5. Перезапустите сервер и выполните `npm run verify:openai`. Проверка проводит настоящее
   интервью через Responses API и завершится ошибкой, если модель добавит неуказанные
   срок, контакт, бюджет или доступные данные. Ключ в вывод не попадает.
6. Выполните `npm start`, создайте аккаунт бизнеса и откройте http://localhost:3000/#create/1.

`npm start` читает `.env` автоматически. При изменении ключа перезапустите сервер.
Ключ передаётся только сервером в OpenAI. Статический сервер не раздаёт `.env`.
Настройка `GET /api/ai/status` сообщает лишь наличие ключа, а не его действительность.

Без ключа включается явно помеченное демонстрационное уточнение без AI.
На `/demo.html` этот режим включён всегда. Он использует шаблоны и локальные данные,
не вызывает OpenAI и отмечен как демо. Ошибка настоящего API не переключает режим автоматически.

Перед готовой карточкой всегда минимум три уточнения. При полном исходном описании уточняются приоритеты и подтверждаются факты. Проверка качества запускается отдельно, без изменения рейтинга полноты. Подробности — [изменения MVP](jury-review.md).

## Что показать жюри

1. Введите: «Нам нужен Telegram-бот для записи клиентов в барбершоп. Срок — 3 недели».
2. Нажмите **Уточнить задачу**. Во время запроса видна анимация анализа.
3. Ответьте на вопросы кнопками или своим текстом. Модель получает описание и всю историю
   после каждого ответа; уже известные сведения не нужно спрашивать повторно.
4. Проверьте цель, пользователей, требования, результат и критерии приёмки в карточке.
   Навыки отображаются тегами. Сложность и размер команды допускают значение «не определено».
5. Измените формулировку, нажмите **Улучшить формулировки** или **Новый вариант карточки**.
   Последнее AI-изменение можно отменить. Допущения и пробелы выделены отдельно.
6. Нажмите **Сохранить черновик** и откройте черновик через кабинет: ответы сохраняются.
7. Дополните контакт, данные и формат взаимодействия, проверьте рейтинг.
8. Отметьте подтверждение и нажмите **Подтвердить и опубликовать**. Только это действие публикует задачу.

## Переиспользуемые части

- `public/ai-flow.js` — конструктор поверх существующего hash router и очереди автосохранения.
- `public/ai-components.js` — индикатор шагов, loading, теги, заметки и преобразование модели карточки.
- `public/demo-ai.js` — автономное шаблонное интервью для показа без ключа.
- `public/api-client.js` — HTTP-адаптер, прежние методы задач и рейтинга сохранены.
- `src/ai.js` — OpenAI Responses API, строгая JSON-схема и проверка входа/выхода.

Генерация и проверка карточки показаны на одном экране: результат сразу доступен для правок.
Генератор использует [Structured Outputs OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs)
через `text.format` с `type: "json_schema"` и `strict: true`. SDK и новые зависимости не добавлены.

## HTTP-контракт

`POST /api/ai/interview`

```json
{
  "action": "answer",
  "description": "Нам нужен Telegram-бот для записи клиентов в барбершоп",
  "answers": [
    { "key": "goal", "question": "Что хотим улучшить?", "answer": "Сократить ручную работу администратора" }
  ],
  "knownFields": { "users": "Клиенты барбершопа", "deadline": "3 недели" },
  "currentTask": null
}
```

Действия: `analyze`, `answer`, `improve`, `regenerate`.
Для двух последних UI передаёт `currentTask` со всеми текущими правками в формате карточки ниже.
`knownFields` — заполненные строковые поля существующего редактора; неизвестные поля не заполняются догадками.

```json
{
  "status": "interview",
  "summary": "Уточним функции и критерии результата",
  "questions": [
    { "id": "requirements", "key": "requirements", "label": "Какие действия должен поддерживать бот?", "chips": ["Запись", "Перенос записи"] },
    { "id": "successCriteria", "key": "successCriteria", "label": "Как проверим результат?", "chips": [] },
    { "id": "data", "key": "data", "label": "Какие данные о расписании уже есть?", "chips": [] }
  ],
  "task": null,
  "provider": "OpenAI",
  "mode": "live"
}
```

Когда информации достаточно, `status` равен `ready`, `questions` — пустой массив,
а `task` содержит следующие обязательные ключи:

```json
{
  "title": "string",
  "problem": "string",
  "goal": "string",
  "targetUsers": ["string"],
  "requirements": ["string"],
  "expectedResult": "string",
  "acceptanceCriteria": ["string"],
  "requiredSkills": ["string"],
  "difficulty": null,
  "estimatedDuration": "string",
  "recommendedTeamSize": null,
  "data": "string",
  "constraints": "string",
  "contact": "string",
  "interactionFormat": "string",
  "missingInfo": ["string"],
  "assumptions": ["string"]
}
```

`difficulty`: `Easy`, `Medium`, `Hard` или `null`; размер команды — целое 1–20 или `null`.
Неизвестные факты — пустые строки/массивы или `null` с пояснением в `missingInfo`.
Модели предписано относить рекомендации и предположения в `assumptions`.
Структурная валидация не гарантирует фактическую точность: бизнес проверяет формулировки вручную.

## Сохранение и ограничения

Описание: 20–3000 символов. Интервью предлагает 3–5 вопросов при нехватке сведений;
при полностью описанной задаче модель может сразу вернуть карточку.
Максимум пять ответов по 1500 символов, после чего оставшиеся пробелы отмечаются в черновике.
Повторение уже отвеченного ключа, невалидный JSON и неправильная форма карточки отклоняются.
Вопросы семантически адаптирует модель; их качество нужно проверить на реальном вызове.

Исходная идея, история, текущий текст и предыдущая карточка сохраняются в строковом поле
`aiSession` JSON-хранилища. Используется прежняя последовательная очередь автосохранения.
Неотправленный ответ при ошибке AI остаётся в поле; доступна повторная попытка.
Если после успешной генерации недоступно сохранение, результат остаётся в редакторе с сообщением об ошибке.

Коды ошибок: 400 (ввод), 422 (отказ модели), 429 (лимит), 502 (провайдер или формат),
503 (нет ключа), 504 (таймаут запроса 45 секунд). Ключ и сырые ошибки провайдера в ответ не включаются.
Модель не имеет инструментов публикации. Генератор не вызывает методы сохранения/публикации сервера;
UI отдельно сохраняет черновик и публикует его после ручного подтверждения.

Полноценная авторизация, квоты AI на пользователя и многопользовательское хранилище
остаются за рамками текущего локального MVP. Это прежний общий демонстрационный кабинет.

## Проверка

`npm test` проверяет существующие сценарии и AI-контракт с подменёнными ответами OpenAI:
контекст, JSON-схему, ошибки, сохранение истории, отсутствие автоматической публикации,
демо-интервью и преобразование редактируемой карточки. `npm run lint` проверяет синтаксис JavaScript.

Ключ в среде разработки агента отсутствовал, поэтому реальный вызов модели не проверен.
В этой среде также недоступен браузер для визуальной проверки.
Перед показом пройдите описанный выше сценарий с ключом и в мобильной ширине окна.

# Мост — интерфейс хакатонного MVP

Платформа, где бизнес публикует задачи, а студенческие команды предлагают решения.
Фронтенд на **HTML, CSS и JavaScript**, без сборки и внешних зависимостей.

## Запуск

Откройте `index.html` в современном браузере двойным щелчком.
Для разработки можно использовать **Live Server** в VS Code или любой статический сервер.
Интернет для работы интерфейса не нужен.

## Что реализовано

- Каталог с поиском, фильтром направлений и сортировкой по рейтингу.
- Создание задачи: описание → пять уточняющих вопросов → редактируемая карточка → подтверждение публикации.
- Рейтинг с разбивкой и подсказками по недостающим сведениям.
- Страница задачи и форма предложения команды.
- Кабинеты бизнеса и команды с переключением демо-роли.
- Сравнение предложений и выбор одной, нескольких или ни одной команды.
- Отправка результата этапа, возврат на доработку и подтверждение баллов.
- Адаптивная вёрстка, состояния загрузки, ошибок и пустых списков.

## Как показать за 3 минуты

1. Откройте каталог в роли «Бизнес». Нажмите «Предложить задачу».
2. Введите проблему, пройдите вопросы, проверьте карточку и отметьте подтверждение.
3. Опубликуйте задачу. Откройте её карточку и переключитесь на роль «Команда».
4. Заполните и отправьте предложение. Переключитесь на «Бизнес».
5. Откройте «Мой кабинет», сравните предложения и подтвердите выбор Orbit.
6. Переключитесь на «Команда» → «Мой кабинет» → «Прогресс проектов».
7. Отправьте описание результата и ссылку на демонстрацию.
8. В роли «Бизнес» подтвердите этап. В кабинете команды появятся 100 баллов.

Для быстрого показа сравнения в задаче «Прогноз спроса для локальной кофейни»
уже есть два демонстрационных предложения: Orbit и «Вектор».

## Передача тиммейтам

| Файл | Назначение |
|---|---|
| `index.html` | Точка входа, шапка, переключение ролей, диалог подтверждения |
| `styles.css` | Все стили и адаптивная вёрстка |
| `app.js` | Экраны, формы, навигация и обработка ответов API |
| `demo-api.js` | **Демонстрационная заглушка** вместо сервера |
| `docs/api-contract.md` | Методы и данные для подключения настоящего API |
| `docs/frontend-scope.md` | Экраны и границы ответственности |

Тиммейту нужно заменить `demo-api.js` адаптером, который объявляет
`window.platformApi` с теми же асинхронными методами, и подключить реального пользователя.
Запросы к серверу и ключи внешних сервисов не нужно добавлять в обработчики экранов.

## Ограничения прототипа

Данные хранятся локально в текущем браузере, между устройствами не синхронизируются.
Если localStorage недоступен, данные остаются только до перезагрузки страницы.
Вопросы формируются по демонстрационным шаблонам; рейтинг проверяет заполненность полей.
ИИ, серверная авторизация, права доступа и фактическое начисление баллов реализуются тиммейтами.
Имена, компании, предложения и контакты в начальных данных вымышлены.
Переключение ролей предназначено для показа экранов, а не для защиты доступа.

## Проверка

Проверены синтаксис обоих JavaScript-файлов и сценарии демонстрационного адаптера:
сортировка, вопросы, черновик, публикация, предложение, защита от дублей,
выбор одной/нескольких/ни одной команды, доработка и подтверждение этапа,
защита от повторного подтверждения.

Автоматизированная визуальная проверка в браузере в текущем окружении недоступна.
Перед выступлением откройте `index.html` и пройдите сценарий выше;
проверьте также узкое окно браузера и пустой результат поиска.

## Улучшения интерфейса

- При создании задачи рядом с формой виден живой предпросмотр карточки.
- Круговой рейтинг показывает полноту и все недостающие критерии с возможной прибавкой баллов.
  На шаге проверки карточки нажатие на подсказку переводит фокус к соответствующему полю.
- Черновик автоматически сохраняется через 700 мс после остановки ввода.
  Индикатор показывает ожидание, сохранение, успех или ошибку; доступна ручная повторная попытка.
  Запросы идут последовательно. Перед публикацией интерфейс дожидается сохранения.
- Предложения представлены карточками с одинаковыми разделами для сравнения.
  Выбранные команды подсвечиваются, их названия появляются в закреплённой нижней панели.
  Решение подтверждается отдельным диалогом со списком команд.

`draft-autosave.js` отвечает только за очередь сохранения. Его нужно оставить при замене
демо-адаптера реальным API; дополнительных библиотек он не требует.

Дополнительно проверены сценарии автосохранения: ввод во время медленного запроса,
объединение быстрых изменений, ошибка и повторная попытка, очистка состояния после публикации.

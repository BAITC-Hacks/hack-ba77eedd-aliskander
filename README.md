# Мост — бизнес-задачи и студенческие команды

Хакатонный проект команды Aliskander. Новый интерфейс объединён с Node.js-сервером
из общей ветки: реальные задачи, отклики, решения бизнеса и этапы сохраняются в JSON-файле.
///
## Запуск

Нужен **Node.js 22.9+**. Внешние зависимости и установка пакетов не требуются.

```sh
npm start
```

Для настоящего AI-интервью сначала скопируйте `.env.example` в `.env` и укажите
`OPENAI_API_KEY`. В PowerShell: `Copy-Item .env.example .env`.
`npm start` автоматически прочитает файл. Модель настраивается через `OPENAI_MODEL`
(по умолчанию `gpt-4o-mini`). Ключ нужен только серверу; `.env` исключён из Git.
После изменения настроек перезапустите сервер.

Без ключа остальные функции работают, а в конструкторе можно явно включить
«Демонстрация без AI API». Это шаблонное демо с соответствующей отметкой, без вызова OpenAI.

Откройте **http://localhost:3000**. Сервер слушает только локальный интерфейс.
Переменные `PORT` и `DATA_FILE` позволяют изменить порт и путь к файлу данных.
По умолчанию данные сохраняются в `data/db.json`; эта папка исключена из Git.
При первом запуске пустой каталог заполняется двумя примерами задач и тремя
проработанными решениями команд. Дальше это обычные записи: их изменения сохраняются,
а существующий файл данных никогда не перезаписывается примерами.

Отдельное автономное демо с вымышленными задачами доступно на **http://localhost:3000/demo.html**.
Его данные хранятся только в браузере и не попадают в серверный каталог.
Для демонстрации без Node можно открыть `public/demo.html` двойным щелчком.
Основной `public/index.html` нужно открывать через сервер.

## Что объединено

- Существующие `src/rating.js`, API задач и предложений, JSON-хранилище и исходные тесты команды сохранены.
- Интерфейс перенесён в `public/`: каталог, поиск, фильтры, кабинеты, создание задачи по шагам.
- `public/api-client.js` переводит поля интерфейса в существующие поля сервера:
  `problem → context`, `outcome → expectedResult`, `success → successCriteria`.
- Сохраняются дополнительные сведения: компания, направление, срок, состав и контакт команды.
- Рейтинг рассчитывается на сервере по исходной шкале команды. Во фронтенде веса не дублируются.
- Живой предпросмотр, подсказки рейтинга, автосохранение и сравнение команд подключены к API.
- Добавлены пакетное подтверждение выбора команд и этапы с отправкой результата,
  доработкой и однократным подтверждением. Данные переживают перезапуск сервера.
- Старые JSON-файлы без `stages` поддерживаются без удаления задач и предложений.

## Показ за 3 минуты

1. В роли «Бизнес» нажмите «Предложить задачу», опишите идею и выберите «Analyze with AI». Ответьте на уточняющие вопросы, проверьте и при необходимости улучшите карточку.
2. Дополните критерии рейтинга, подтвердите публикацию.
3. На странице задачи выберите роль «Команда» и отправьте предложение с идеей и планом.
4. Вернитесь в роль «Бизнес» → «Мой кабинет» → сравнение предложений.
5. Нажмите «Выбрать» у нужных предложений и подтвердите сотрудничество. Любой вариант можно вручную отклонить.
6. В роли «Команда» откройте «Прогресс проектов» и отправьте описание и ссылку на результат.
7. В роли «Бизнес» подтвердите этап либо верните его на доработку с комментарием.
8. После подтверждения в кабинете команды отображаются 100 баллов.

Для быстрого сравнения двух готовых предложений используйте отдельную страницу `/demo.html`.

## Проверка

```sh
npm test
npm run lint
```

Проверены исходные сценарии сервера и новый адаптер интерфейса через реальный HTTP:
сохранение и восстановление черновика, неизменность шкалы рейтинга, публикация,
идея/план/ссылка предложения, выбор одной/нескольких/ни одной команды,
доработка, подтверждение этапа, сохранение после перезапуска и защита от повторного начисления.
AI-тесты проверяют структуру запроса, передачу контекста, ошибки провайдера,
отсутствие автоматической публикации и сохранение ответов. Они подменяют ответы OpenAI:
реальный запрос требует настроенного ключа и отдельной проверки.

Визуальная проверка в браузере в среде агента недоступна; перед выступлением
проверьте сценарий в обычном браузере и в узком окне.

## Ограничения MVP

- Как и в исходном сервере, полноценной авторизации нет: бизнес использует общий кабинет,
  а переключение ролей служит демонстрации. Название активной команды можно изменить в шапке; это не вход в аккаунт.
  Не публикуйте сервер с реальными закрытыми данными до добавления авторизации и проверки прав.
- Основной конструктор использует OpenAI при наличии серверного ключа. Автономное демо и старый `/api/questions` используют шаблоны. Ответы модели требуют проверки бизнесом.
- Хранилище рассчитано на один процесс сервера; чат, уведомления и совместное редактирование отсутствуют.
- В этой версии выбранной команде создаётся один этап «Демонстрация рабочего прототипа» на 100 баллов.

Подробности маршрутов: [docs/api-contract.md](docs/api-contract.md). Настройка и демонстрация AI: [docs/ai-task-generator.md](docs/ai-task-generator.md).


## Соответствие минимальным требованиям

| Модуль | Реализация |
|---|---|
| Конструктор | Свободное описание, проверка полноты, минимум 3 вопроса, редактирование и ручное подтверждение |
| Карточка | Название, контекст, потребность, пользователи, данные, ограничения, результат, критерии успеха, контакт, формат взаимодействия |
| Рейтинг | Серверный балл 0–100, разбивка, недостающие сведения, пересчёт после ввода |
| Каталог | Все опубликованные задачи, сортировка по баллам, совместимые фильтры темы и готовности |
| Отклики | Идея, план, ссылка на прототип; повторные предложения от любой демонстрационной команды без лимита количества |
| Решения бизнеса | Отдельные «Выбрать» / «Отклонить» у каждого отклика, финальное ручное подтверждение сотрудничества |

Для проверки разных команд выберите роль «Студенческая команда» и измените название в шапке.
Название идентифицирует команду только в демо, не заменяет серверную авторизацию.
Отклики одной команды рассматриваются независимо. После подтверждения сотрудничества
для каждой выбранной команды создаётся один этап, даже если выбрано несколько её вариантов.

Шкала рейтинга команды сохранена. Потребность и формат взаимодействия отображаются
отдельными пунктами проверки карточки без дополнительных баллов сверх исходных 100.

## AI Match — насколько задача подходит участнику

Участник заполняет профиль: навыки, опыт, проекты, интересы, уровень и доступные часы.
В каталоге и на странице задачи появляется Match 0–100% с объяснением пяти критериев.
Бизнес видит снимок профиля и Match в новых откликах; выбор команд остаётся ручным.

Быстрый показ: **http://localhost:3000/demo.html#match-demo** — профиль Ali, CRM Dashboard,
четыре из пяти навыков и вычисленные **87% Strong Match**. Работает без OpenAI.
Для обычного сценария выберите студенческую роль → «Мой профиль» → сохраните данные.
В конструкторе задачи укажите навыки, сложность и нагрузку в часах в неделю.

Процент рассчитывает единый алгоритм. Кнопка OpenAI в подробностях добавляет только
текстовое объяснение, используя уже настроенный серверный ключ. При ошибке AI
число и объяснение по критериям остаются доступны. GitHub-технологии вводятся вручную.

Формула, API, ограничения и сценарий показа: [docs/ai-match.md](docs/ai-match.md).
